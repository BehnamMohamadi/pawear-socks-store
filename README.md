# PAWEAR — فروشگاه جوراب پاور

نسخه یکپارچه شامل سه فاز: بک‌اند Express/Mongoose، پنل مدیریت بر مبنای gold-store و فرانت‌اند فارسی EJS با رندر سمت سرور. فرانت با الهام اولیه از PAWEAR_EXPRESS_EJS_SSR_BASE_v3، مستقلاً با طراحی لوکس بازطراحی شده و کاتالوگ، حساب، سبد و سفارش به دیتابیس واقعی متصل‌اند. راهنمای طراحی و پنج اندازه در docs/FRONTEND-DESIGN.fa.md است.

## اجرای همین نسخه روی سیستم فعلی

فایل .env این سیستم تنظیم شده است؛ با .env.example جایگزینش نکن.

```powershell
npm run db:local
npm run dev
```

- فروشگاه: http://127.0.0.1:3000
- ورود مدیر: http://127.0.0.1:3000/admin/login
- مشخصات ادمین ساخته‌شده: artifacts/local-admin.txt؛ این فایل و .env خصوصی و خارج از Git هستند.
- MongoDB اختصاصی پاور روی 27028 با Replica Set به نام pawearDev اجرا می‌شود. db:local سرویس MongoDB دیگر سیستم را تغییر نمی‌دهد.
- پس از تغییر .env، سرور را با Ctrl+C متوقف و دوباره اجرا کن.
- هنوز کالای ساختگی در دیتابیس اصلی ایجاد نشده؛ از پنل دسته، زیردسته، جوراب و باکس واقعی خودت را ثبت کن.

## نصب روی سیستم دیگر

Node.js نسخه 22.12 یا بالاتر و MongoDB لازم است.

1. npm ci
2. .env.example را در .env کپی کن.
3. JWT_SECRET را با خروجی دستور زیر پر کن؛ نام متغیرها نباید بک‌اسلش داشته باشند و URL باید متن ساده باشد، نه لینک Markdown.
4. npm run db:local؛ اگر MongoDB در مسیر دیگری نصب است، MONGOD_BINARY را تنظیم کن.
5. npm run setup:admin؛ فقط در توسعه، مدیر محلی جدید با رمز تصادفی می‌سازد و مشخصات را در artifacts/local-admin.txt می‌نویسد. حساب قبلی را بازنویسی نمی‌کند.
6. npm run dev

```powershell
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
```

برای Replica Set اختصاصی دیگر، MONGODB_URI را تنظیم کن و db:local را اجرا نکن. اتصال به دیتابیس قبلی گلد استور مجاز نیست؛ مدل‌ها متفاوت‌اند.

ساخت مدیر با مقادیر انتخابی: ADMIN_FIRSTNAME، ADMIN_LASTNAME، ADMIN_PHONENUMBER و ADMIN_PASSWORD در .env و سپس npm run seed:admin. اگر مدیر وجود داشته باشد، رمز حفظ می‌شود. بازنشانی صریح رمز مدیر: npm run seed:admin -- --reset-password؛ نشست‌های قبلی باطل می‌شوند. شماره متعلق به مشتری خودکار مدیر نمی‌شود.

## امکانات پنل

- داشبورد فروش پرداخت‌شده، تعداد سفارش/کاربر/کالا، موجودی کم و صف بررسی پرداخت.
- ساخت و ویرایش دسته و زیردسته، تصویر دسته، ترتیب و فعال/غیرفعال‌کردن.
- جوراب: نام، کد، دسته، جنسیت، قیمت تومان، موجودی، شرح، مشخصات و گالری/جلد.
- باکس: ترکیب جوراب‌ها و تعداد هرکدام، تخفیف، محاسبه قیمت و موجودی، تصویر و انتشار.
- سفارش: اقلام و آدرس ثبت‌شده، اجزای باکس هنگام خرید، تلاش‌های پرداخت، ثبت ارسال با کد رهگیری و سپس تحویل.
- پرداخت: فیلتر وضعیت، بررسی پرداخت دیرهنگام، ثبت تأمین موجودی یا بازپرداخت انجام‌شده در خارج از سایت.
- کاربران: افزودن، ویرایش، نقش و وضعیت حساب. مشاهده سبدهای خرید و تاریخچه سفارش.
- فهرست‌ها جستجو/فیلتر متناسب و صفحه‌بندی دارند؛ صفحات پنل نیازمند نقش admin هستند.

## قواعد محصول و خرید

هر طرح یک Product مستقل و فری‌سایز است. price قیمت یک جفت به تومان و stock تعداد قابل‌فروش بدون رزروهای پرداخت است. هر باکس حداقل دو جفت دارد و می‌تواند چند جفت از یک مدل داشته باشد. باکس موجودی مستقل ندارد؛ موجودی برابر کمینه نسبت موجودی هر جزء به تعداد لازم آن است. قیمت جمع اجزا پس از تخفیف صحیح ۰ تا ۹۹ درصد و گرد شده به تومان است.

موجودی مصرفی جوراب تکی و باکس در یک سبد تجمیع می‌شود. تغییر تعداد و شروع پرداخت از فروش بیش از موجودی جلوگیری می‌کنند. غیرفعال‌کردن کالا اطلاعات سفارش قبلی را پاک نمی‌کند. باکس دلخواه مشتری برای نسخه آینده است.

```text
Cart → Order pending → Payment pending → confirmed → shipped → delivered
```

Checkout قیمت روز را محاسبه می‌کند؛ POST /api/orders با addressId سفارش را آماده می‌کند. قیمت، ترکیب و آدرس snapshot می‌شوند و آماده‌سازی ۱۵ دقیقه اعتبار دارد. شروع پرداخت قیمت و سبد را دوباره بررسی و موجودی را در تراکنش رزرو می‌کند؛ سبد خالی می‌شود. مهلت پرداخت ۱۰ دقیقه است؛ worker هر ۱۵ ثانیه رزرو منقضی را یک بار آزاد می‌کند. Callback تکراری دوباره موجودی کم نمی‌کند.

پرداخت موفق دیرهنگام به review می‌رود. مدیر می‌تواند با تأمین موجودی سفارش را تأیید کند، یا بازپرداختی که واقعاً انجام داده با شماره پیگیری ثبت کند. گزینه refunded انتقال بانکی انجام نمی‌دهد. نتیجه نهایی قابل تغییر نیست.

SHIPPING_AMOUNT_TOMAN هزینه ثابت ارسال به تومان است؛ صفر یعنی رایگان. تخفیف کددار، ارسال استانی و فرآیند مرجوعی بعد از تحویل در این نسخه پیاده نشده‌اند.

## ورود دوحالته

در /login، /signup و /admin/login دو تب واضح رمز ثابت و کد یک‌بارمصرف نمایش داده می‌شود. این صفحات هدر و فوتر فروشگاه ندارند. کاربر تازه در فرم OTP نام و نام خانوادگی هم وارد می‌کند. پس از ورود با OTP تا ۱۰ دقیقه از /account می‌تواند رمز ثابت بگذارد. در زمان قطعی پیامک، حسابی که رمز ثابت دارد با همان رمز وارد می‌شود.

OTP شش رقم، دو دقیقه اعتبار، ۶۰ ثانیه فاصله ارسال و حداکثر پنج تلاش دارد. فعلاً SMS_PROVIDER=console کد را فقط در ترمینال توسعه چاپ می‌کند؛ پیامکی ارسال نمی‌شود و کد در پاسخ API نیست. سرویس پیامکی آینده در services/auth-services/sms-service.js متصل می‌شود. رمز ثابت برای کاربر فاقد رمز باید قبلاً تنظیم شود.

JWT در کوکی HttpOnly/SameSite قرار می‌گیرد و در production فقط HTTPS دارد. خروج از حساب و تغییر رمز، نشست‌های قبلی را باطل می‌کند. ثبت‌نام با رمز فعلاً شماره را تأیید نمی‌کند؛ سیاست تأیید مالکیت شماره قبل از فروش عمومی باید مشخص شود.

## سئو و عملکرد

صفحات محصول، باکس و فروشگاه محتوای اصلی را در HTML سرور دارند. canonical و توضیحات صفحه، عنوان فارسی، یک H1 در خانه، sitemap.xml و robots.txt اضافه شده‌اند. Product/Offer JSON-LD قیمت واقعی را با واحد IRR (تومان ×۱۰) و موجودی واقعی اعلام می‌کند؛ امتیاز یا نظر ساختگی ندارد. صفحات ناموجود و صفحات خارج از محدوده صفحه‌بندی 404 واقعی می‌دهند.

حساب، خرید و مدیریت noindex هستند؛ در محیط توسعه کل سایت noindex و robots بسته است. فیلترهای جستجو noindex دارند و صفحه‌بندی لینک HTML دارد. SITE_URL دامنه اصلی canonical و sitemap است؛ در production باید HTTPS واقعی باشد. آدرس محصول هنگام تغییر نام ثابت می‌ماند و فیلد slug پنل پس از ساخت فقط خواندنی است؛ تغییر مستقیم آن از API نیازمند برنامه انتقال URL است.

شش تصویر اختصاصی تولید شده و مجموع نسخه‌های WebP حدود ۹۲۴ کیلوبایت است. فونت وزیرمتن به‌صورت محلی بارگذاری می‌شود. پرامپت‌ها و محل فایل‌ها در docs/pawear-image-prompts.json ثبت شده‌اند.

جزئیات فنی و کارهای قبل از انتشار در docs/SEO.fa.md. این موارد تضمین رتبه یا نتیجه Core Web Vitals روی سرور نهایی نیستند.

## Postman و تست

docs/PAWEAR.postman_collection.json را Import کن؛ ۹۰ درخواست برای هر سه فاز دارد. baseUrl به /api و siteUrl به ریشه سایت اشاره می‌کنند. adminPassword، phone و password را فقط محلی تنظیم کن. Cookie jar باید روشن باشد. ایجادهای موفق شناسه‌ها را خودکار ذخیره می‌کنند. ابتدا ورود مدیر و ساخت کاتالوگ، سپس ورود مشتری و جریان خرید را اجرا کن. مجموعه شامل عملیات تغییردهنده است؛ کل آن را روی فروشگاه اصلی به‌صورت خودکار Run نکن.

```powershell
npm run check
npm test
npm run postman:build
```

تست‌ها MongoDB آزمایشی جدا با پورت آزاد و نام تصادفی می‌سازند؛ دیتابیس اصلی دست نمی‌خورد. مسیر MongoDB را می‌توان با MONGOD_BINARY یا اتصال تست را با TEST_MONGODB_URI تعیین کرد. ۲۲ تست شامل هم‌زمانی موجودی/OTP/آدرس، پرداخت، امنیت، SSR، کنترل دسترسی پنل، JSON-LD، sitemap و اجرای JavaScript واقعی مرحله آماده‌سازی سفارش موفق شده‌اند.

## قبل از فروش عمومی

درگاه فعلی mock و پرداخت‌ها آزمایشی‌اند. آداپتور زرین‌پال وجود دارد اما با پذیرنده واقعی تست نشده است. برای انتشار: دامنه و HTTPS، Merchant ID، callback، مبلغ ارسال، اطلاعات تماس و سیاست‌های فروشگاه را تنظیم کن؛ پرداخت واقعی و پیامک را با سرویس خودت آزمایش کن. STORE_CONTACT، STORE_SHIPPING_POLICY، STORE_TERMS و STORE_PRIVACY_POLICY متن‌های عمومی فروشگاه را تعیین می‌کنند.

این پروژه Node.js و MongoDB Replica Set می‌خواهد؛ خروجی استاتیک نیست. برای چند پردازش سرور، rate limiter مشترک لازم است. راهنمای API در docs/API.fa.md و بررسی مبنا در docs/BASELINE-REVIEW.fa.md قرار دارد.
