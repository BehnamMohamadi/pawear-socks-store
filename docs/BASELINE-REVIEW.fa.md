# بررسی مرجع و تصمیم‌های بک‌اند پاور

مبنای اصلی: [gold-store-backend-adminpanel-dashboard](https://github.com/BehnamMohamadi/gold-store-backend-adminpanel-dashboard)، commit b59823eac874e9eea8d5510a4cbfe7ee57f17dcb.
مرجع جوراب و باکس: [jewelry](https://github.com/BehnamMohamadi/jewelry)، commit 8e222ea911011724a762996a8c23fad45cfdf148.

بررسی استاتیک مسیرها، مدل‌ها، کنترلرها، اعتبارسنجی‌ها، middleware و سرویس‌های خرید انجام شد. این گزارش گواه تست درگاه واقعی یا ممیزی امنیتی مستقل نیست.

## ساختار شناسایی‌شده

هر دو پروژه JavaScript/CommonJS، Express، Mongoose، Joi، bcrypt، JWT، cookie-parser، dotenv، Morgan، Multer و Sharp دارند. پروژه مبنا Helmet و express-rate-limit هم دارد. پنل با EJS و JavaScript مرورگر نوشته شده است. قیمت‌گذاری طلا در سرویس جدا، سفارش و Payment مستقل و آدرس snapshot‌شده دارد. این جداسازی لایه‌ها حفظ شد.

در jewelry مدل اجرایی جوراب در models/product-model.js است؛ schema/productSchema.js ساختار قدیمی طلاست و مبنای مدل اجرایی نیست. محصول جوراب price و quantity دارد؛ باکس products[{product,quantity}] و discount دارد و قیمت با populate محاسبه می‌شود. Cart جدید Product/Box دارد، اما router آن در api-route.js نصب نشده و برخی controllerهای اشاره‌شده در cart-route.js export نشده‌اند. Basket قدیمی جدا از این Cart است.

## ایرادهای مهم و اقدام جدید

| یافته مرجع | اقدام پاور |
|---|---|
| User.create در register و addUser بدون حذف password پاسخ می‌دهد؛ select:false پاسخ create را حذف نمی‌کند | transform مدل، password و tokenVersion را از تمام JSONهای کاربر حذف می‌کند |
| ApiFeatures فیلتر ورودی را روی فیلتر عمومی isActive سوار می‌کند | فهرست مجاز فیلتر و حفظ شرایط محافظت‌شده query |
| انتخاب فیلد با +password می‌تواند فیلتر ساده نام را دور بزند | حذف + و مسدودسازی نام‌های حساس |
| سفارش طلا و snapshot وابسته به goldWeight/karat/wage است | snapshot جوراب/باکس، قیمت تومانی و اجزای ثابت |
| cart jewelry موجودی اجزای باکس و مجموع مصرف تکی/باکسی را نمی‌سنجد | تجمیع موجودی Product برای همه ردیف‌های سبد |
| کد SKU با آخرین کد + ۱ هم‌زمان تکرار می‌شود؛ kids در نگاشت کد وجود ندارد | SKU تصادفی با unique index |
| adminUpdateOrder می‌تواند سفارش پرداخت‌نشده را confirmed کند | گذار محدود confirmed→shipped→delivered؛ تأیید فقط از سرویس پرداخت |
| fallback پرداخت بدون transaction و اصلاح review چند نوشتن جدا دارد | Replica Set اجباری؛ رزرو، آزادسازی و review با تراکنش |
| پس از logout توکن قبلی تا انقضا معتبر می‌ماند | tokenVersion و باطل‌سازی نشست‌ها |
| account DELETE مسیر دیگری برای غیرفعال‌کردن خودِ ادمین دارد | جلوگیری از این عمل در مسیر حساب شخصی |
| delete محصول ارجاع سبد/باکس را قطع می‌کند | غیرفعال‌سازی محصول/باکس و حفظ snapshot |
| ورودی JSON خراب می‌تواند به 500 نگاشت شود | خطای 400 برای JSON نامعتبر و 413 برای حجم زیاد |
| تغییر شماره از حساب شخصی بدون اثبات مالکیت | شماره در ویرایش حساب شخصی مجاز نیست |
| config.env در مخزن عمومی jewelry قرار گرفته | از آن استفاده نشد؛ تنظیمات فقط از .env محلی و .env.example؛ اگر مقدار واقعی در آن بوده، کلیدها باید تعویض شوند |

## تغییرات آگاهانه نسبت به پروژه مبنا

موجودی هنگام شروع پرداخت رزرو می‌شود، نه پس از بازگشت موفق درگاه. قیمت آماده‌سازی ۱۵ دقیقه اعتبار دارد؛ پنجره پرداخت ۱۰ دقیقه است. پایان پنجره موجودی را پس می‌دهد و پرداخت دیرهنگام review می‌شود. MongoDB standalone دیگر مسیر کاهش ایمنی ندارد.

در مدل جدید هر stock یک جفت جوراب قابل‌فروش است. باکس انبار جدا ندارد. موارد سایز/رنگ و باکس‌ساز مشتری به درخواست صاحب فروشگاه فعلاً ساخته نشده‌اند. بخش UI پس از درخواست «فقط بک‌اند» متوقف شد.

## مواردی که هنوز اتصال بیرونی لازم دارند

پنل پیامکی هنوز انتخاب نشده؛ SMS واقعی پیاده‌سازی ارائه‌دهنده ندارد. سرویس زرین‌پال موجود حفظ شده ولی Merchant واقعی و پرداخت واقعی تست نشده‌اند. آدرس سرور، HTTPS، مقدار ارسال و واحد درگاه قبل از بهره‌برداری باید مشخص شوند. قرارداد API و شیوه اجرای تست در README و docs/API.fa.md آمده است.
